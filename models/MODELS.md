# Запуск моделей

В проекте сравниваются Grounding DINO tiny, OWLv2 base и Qwen3-VL-2B-Instruct.
Итоговые предсказания на 400 фотографиях находятся в `../model_results_400/`,
метрики и анализ ошибок в `../eval/`. Здесь описаны параметры инференса
и обработка незавершённых ответов.

## Запуск

Из каталога `models/`, Python 3.12. Команды ниже повторяют исходный прогон
до замены трёх фотографий. Запуск на окончательном наборе описан в
[инструкции воспроизведения](../docs/reproduction.md).

```bash
python3 -m venv .venv-models
.venv-models/bin/pip install -r requirements-models.txt
python3 -m venv .venv-qwen
.venv-qwen/bin/pip install -r requirements-qwen-macos.txt
PYTHON_BIN=.venv-models/bin/python QWEN_PYTHON_BIN=.venv-qwen/bin/python bash scripts/run_comparison.sh
```

На Mac используется MPS с разрешённым CPU fallback для неподдерживаемых
операций PyTorch (у DINO это, например, cummax), на NVIDIA: CUDA, иначе CPU. Модели запускаются
последовательно. Фото скачиваются по исходным URL из манифеста, сохраняются
в исключённой из git папке `inaturalist_dataset/photos/`. Путь с обратными
слешами из исходных файлов корректно читается и на macOS/Linux.

Приведены окружения, использованные на Apple M3: детекторы: PyTorch 2.7,
Qwen: PyTorch 2.15 с SDPA. У Qwen на старом MPS runtime возникала авария;
обновление проверено отдельно. Версии записаны в metadata. После загрузки всех весов
и фото можно добавить `HF_HUB_OFFLINE=1` перед командой полного запуска.

Повторный запуск пропускает успешно обработанные фото. Ошибки пишутся в
`*.errors.jsonl`. Они не считаются отрицательными ответами. После трёх ошибок
подряд запуск модели останавливается. Можно отдельно продолжить одну модель:

```bash
.venv-qwen/bin/python scripts/run_models.py --model qwen --output results/qwen/candidates.jsonl
```

Для отладки есть `--limit 1`, `--photo-ids 123 456`, `--device cpu` и `--cached-only`.
Последний флаг считает только уже скачанные фото, но всё равно сообщает
о неполной выборке. Частичный файл не получится экспортировать как полный.

## Файлы исходного прогона

- `results/dino/predictions_t0.25.jsonl`: основной вариант Grounding DINO tiny.
- `results/owlv2/predictions_t0.25.jsonl`: основной вариант OWLv2 base.
- `results/qwen/predictions.jsonl`: Qwen3-VL-2B-Instruct.
- Варианты `t0.15` и `t0.40` для первых двух моделей: эксперимент с порогом.
- `candidates.meta.json` рядом с каждым запуском: настройки, версия весов,
  версии библиотек и время загрузки.

Пример строки предсказаний:

```json
{"photo_id": 123, "boxes": [{"left": 0.1, "top": 0.2, "width": 0.5, "height": 0.4}], "scores": [0.81], "status": "ok", "elapsed_seconds": 1.2}
```

Это пример структуры, не результат модели. Координаты от 0 до 1 относительно
исходного изображения. `boxes: []`: модель не нашла взрослых бабочек/мотыльков;
строка для такого фото сохраняется обязательно. В каждой строке также есть
модель, размер и SHA-256 исходного фото, признак первого прогревочного вызова.
У Qwen `scores` содержит `null`: модель генерирует координаты текстом и
сопоставимой с детекторами уверенности у нас нет. Исходный текст Qwen сохранён
в `raw_text`. Первоначальный запуск сохранён без изменений в
`results/qwen/candidates.jsonl`: 395 полных ответов и 5 обрывов на 512 токенах.
В основном `predictions.jsonl` эти пять строк заменены повторным инференсом.
395 остальных ответов не менялись.

Повторный запуск: тот же commit весов, новый промпт `prompts/qwen_complete.txt`,
1024 px, максимум 4096 токенов, repetition penalty 1.1. Принимаются только
ответы с EOS и целым JSON. Четыре фото завершились. Для фото 247404664
модель снова исчерпала лимит. Его обработали по 16 перекрывающимся фрагментам:
сетка 4×4, расширение каждой ячейки на 10% её размера с каждой стороны,
768 px, 1024 токена, repetition penalty 1.15. Рамки переведены в координаты
оригинала, дубли удалены NMS IoU 0.5 с приоритетом рамок дальше от края фрагмента.
Этот приоритет геометрический, уверенности модели у Qwen по-прежнему нет.

У строки с фрагментами `raw_text: null`: единого текстового ответа на целое
фото нет. Все исходные ответы и границы фрагментов находятся в `tiles`;
`completion_method: "overlapping_tiles"` явно выделяет этот случай.
Рамки вручную не исправлялись. Пять повторно обработанных фото имеют
другие параметры генерации. После замены двух из них в итоговом наборе
осталось три таких результата.

Воспроизведение дополнения и экспорта:

```bash
PYTORCH_ENABLE_MPS_FALLBACK=1 .venv-qwen/bin/python scripts/complete_qwen.py
python3 scripts/export_predictions.py --source results/qwen/completed_candidates.jsonl --output results/qwen/predictions.jsonl
```

Настройки повторных запусков: `retry_full.meta.json` и `tiles/*.meta.json`.
Сводная история: `completed_candidates.meta.json`. Ошибки полнокадровых
попыток сохранены в `*.errors.jsonl`. Обрыв не подменяется пустой разметкой.

## Настройки сравнения

Grounding DINO получает `butterfly. moth.`, OWLv2 получает два текстовых запроса
`a photo of a butterfly` и `a photo of a moth`. Оба класса объединяются в один
целевой класс. Дубликаты убираются общим NMS с IoU 0.5. Кандидаты сохраняются
при score ≥ 0.10. Основной порог: 0.25. Порог текста DINO: 0.25.

Qwen получает инструкцию найти всех взрослых бабочек, мотыльков и моль,
исключить гусениц, куколок и других насекомых, вернуть JSON с рамками xyxy
в шкале 0–1000. Изображение уменьшается с сохранением пропорций до 768 px
по длинной стороне. Для DINO и OWLv2 зафиксирован PIL backend обработки изображений,
для Qwen используются torchvision и attention SDPA. Генерация детерминированная, максимум 512 новых токенов,
FP16 на MPS/CUDA и FP32 на CPU. В исходном запуске NMS к Qwen не применяется. Полный промпт есть
в `scripts/run_models.py` и metadata. Категория, таксон и ожидаемый класс
из метаданных не передаются ни одной модели.

Время каждой фотографии включает препроцессинг, модель, постпроцессинг и
синхронизацию устройства. Скачивание и загрузка весов исключены. Первые вызовы
каждого процесса помечены `warmup: true`. Для сравнения скорости их следует
исключать и указывать устройство. Варианты порогов получены из одного запуска:
их время инференса одинаковое, экспорт не считается повторным инференсом.

Для пяти дообработанных фото `elapsed_seconds` включает исходный вызов и
успешный повтор (сумму вызовов фрагментов для фото 247404664). Компоненты
сохранены отдельно. Время неуспешной полнокадровой попытки не было записано
и в сумму не входит. Эти пять строк нужно исключить из сравнения скорости
исходных конфигураций.

Для DINO и OWLv2 рассчитаны precision, recall и F1 при score 0.15/0.25/0.40
и IoU 0.5/0.75. Основной порог 0.25 зафиксирован заранее. Остальные пороги
исследованы на той же выборке для анализа чувствительности. Результаты
сохранены в `../eval/results/`.

Источники API и весов:
[Grounding DINO](https://huggingface.co/IDEA-Research/grounding-dino-tiny),
[OWLv2](https://huggingface.co/google/owlv2-base-patch16-ensemble),
[Qwen3-VL](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct).

Проверки преобразования координат, NMS, парсинга Qwen и запрета экспорта
неполной выборки: `python3 -m pytest -q tests` (требуется pytest).
